# 확장 계획 2 · M7 ~ M11 (설계 2026-11-06)

A · B · C · M5 · M6 설계는 [ROADMAP.md](../ROADMAP.md)의 "확장 계획" 절. 여기는 그 뒤에 이어지는 M7 ~ M11.
묶음은 git worktree에서 동시에 구현하고 stage2에 합친다. 구현한 행은 "구현"으로 표시하고, 설계와 달라진 점을 그 행에 적는다.
숫자는 실테스트 전 초안이다. 조정할 만한 값은 `config/sanupcraft.json`(SanupcraftConfig)으로 뺀다.

M7 구현 메모 (설계와 다른 점 · 정한 것, 코드는 `storage/`):
- S1: 업그레이드는 아이템 둘 — 용량 업그레이드(×2, 2개까지)와 넘침 버림 업그레이드. 웅크리고 빈손 우클릭으로 하나씩 뺀다 (넘칠 용량 업그레이드는 안 빠짐). 앞면 좌클릭은 부수지 않으니 옆 · 위에서 캔다. 부숴도 내용물 · 업그레이드가 서랍 아이템에 남는다 (컴포넌트 `sanupcraft:drawer_contents`). 비교기 신호. 철 서랍 레시피에 강철 주괴 1 (강철 단계).
- S2: "탱크"는 이 갈래에 탱크 블록이 없어 빠졌다 (`Container` 블록이면 다 붙는다). 페이지 대신 굴림 막대. 기계처럼 면마다 칸이 다른 블록은 깔때기와 같은 규칙(관이 닿은 면의 칸)을 따른다. 자동 제작대는 보관함으로 보지 않는다. 관 수 한도 512(설정), 관 근처가 바뀌거나 2초가 지나면 다시 찾는다. 단말 증기는 화면이 열려 있는 동안만 틱당 1 (저장 1000). 목록은 바닐라 칸 동기화 대신 따로 패킷(서버 → 화면, 클릭은 화면 → 서버, 서버가 다시 확인).
- S3: 화면을 닫으면 제작 칸의 것은 네트워크로 (안 들어가면 인벤토리로) 돌아간다.
- S4: "네트워크에서 재료"는 옆 재고 유지기가 넣어 주는 것으로 했다. 10틱마다 한 번 만든다. 쓰고 남는 것(빈 양동이 등)은 위로 떨군다.
- S5: 한 번에 최대 4번 몫까지 넣고, 이미 넣어 둔 몫이 있으면 기다린다. 옆 자동 제작대 · 기계의 결과는 창고로 거둔다. 기계의 연료 · 증기는 따로.
- S6: 기본판 레시피는 강철판 · 엔더 진주 (엔드 전에도 만든다), 셜커 껍데기판이 엔드 단계. 단말 청크가 불러와져 있어야 하고, 아니면 안내만 한다. 연결은 단말에 우클릭.
- 설정 9개 (`drawer.*`, `storage.*`, `autocrafter.*`, `stocker.*`), 발전 과제 5개 (창고 정리 → 한눈에 창고 → 손 안 대고 제작 → 언제나 가득, 어디서나 창고), 실테스트 `storage` 단계.

**M8 I4 구현 메모 (렌치 · 면 설정)** — 코드 `wrench/`(렌치) · `factory/MachineFaces`(면 설정), GameTest `SanupcraftM8cGameTest`, 실테스트 `wrench`.
- **모드 둘**: 돌리기(기본) ↔ 면 설정, **허공에 우클릭**으로 바꾼다 (컴포넌트 `sanupcraft:wrench_faces`, 툴팁 · 액션바에 표시). "윗면은 돌리기, 옆면은 면 설정"처럼 면으로 나누면 위 · 아래 면을 설정할 수 없어서 모드로 나눴다. 웅크리고 우클릭(집기)은 모드와 상관없다.
- 블록 우클릭은 기계 화면 열기보다 먼저 받아야 해서 아이템 `useOn`이 아니라 Fabric `UseBlockCallback`으로 처리한다 (클라이언트는 보내기만, 판단 · 안내는 서버). 렌치를 들고 블록을 누르면 블록 화면은 안 열린다.
- **돌리기**: "facing" 방향 속성이 있는 블록. 가로 4방향은 `rotate(CLOCKWISE_90)`(블록 규칙대로, 없으면 시계 방향), 그 밖(6방향 · 깔때기 5방향)은 `Direction` 순서로 다음 허용 방향. 바닐라는 침대 · 문 등 두 칸짜리, 큰 상자, 늘어난 피스톤 · 피스톤 머리를 빼고, 돌린 뒤 `canSurvive`가 아니면(벽 횃불 · 사다리 등) 안 돌린다. 부술 수 없는 블록(단단함 < 0)도 안 돌린다. 다중 블록 제어기를 돌리면 다음 모양 확인에서 풀린다.
- **집기**: 이 모드의 블록 엔티티 블록만. 바닐라 "데이터째 집기"(`addBlockDataToItem`)와 같은 방식: `saveCustomOnly` → `removeComponentsFromTag` → `minecraft:block_entity_data` + 블록 엔티티 컴포넌트(칸 → `minecraft:container`, 탱크 · 서랍 · 경험치 탱크는 원래 컴포넌트). 놓으면 바닐라 `BlockItem`이 되살린다. 블록을 지울 때 `UPDATE_SKIP_BLOCK_ENTITY_SIDEEFFECTS`로 내용물 쏟기를 건너뛴다 (복사 방지). 인벤토리에 넣고 가득이면 발밑에. 잠긴 엔더 수신기 · 송신기와 단말은 `canManage`(주인 · 팀 · OP)만. **엔더 닻은 못 집는다** (붙잡은 청크 목록을 들고 옮기면 엉키므로, 캐서 옮김). 제단은 블록 엔티티가 없어 원래 못 집는다. 굴착기는 진행(층 · 칸)째 옮겨진다.
- **면 설정**: `MachineBlockEntity`(모든 기계 종류)만. 면 6개(앞 · 뒤 · 왼쪽 · 오른쪽 · 위 · 아래, 기계가 보는 쪽 기준 — 왼쪽은 앞에서 볼 때)에 기본 / 넣기 / 빼기 / 둘 다 / 막기, 저장 키 `faces` (6글자, 전부 기본이면 안 씀). 기본 = 예전 규칙(위 → 재료, 옆 → 연료, 아래 ← 결과). 넣기 = 재료 · 연료 칸(재료 거름 · 합금로 교착 막기는 그대로), 빼기 = 결과 · 부산물 · 연료 칸의 빈 양동이, 둘 다 = 전부, 막기 = 없음. 기계 기준이라 렌치로 돌리면 설정도 같이 돈다. 누를 때마다 액션바에 "위 면: 넣기" + 여섯 면 요약. 따로 보기 화면은 안 만듦.
- 깔때기 · 창고 관 · 굴착기 · 필터 깔때기 등 `WorldlyContainer` 규칙을 쓰는 것은 저절로 따른다. **벨트 · 분류기**는 닿은 면이 기본이면 예전처럼(연료는 옆, 나머지는 위 면 규칙), 면을 정해 두었으면 그 면으로만 넣는다 (`BeltBlockEntity.insert`). 재고 유지기(S5)는 면과 상관없이 칸에 바로 넣는다.
- 레시피: 강철 주괴 3 + 철판 (`S S / P / S`). 발전 과제 "돌리고 조이고" (부모 = 강철).

- 보스 예고: 수호자는 돌진 방향을 잠글 때, 파수꾼은 증기 분출 방향을 잠글 때 예고음 (원래 시작 소리는 그대로). 체력이 절반 아래로 처음 내려가면 화남 소리 + 연기 · 입자 (수호자 = 치명타 불꽃, 파수꾼 = 불꽃), 불러온 보스는 체력으로 다시 정해서 또 울리지 않는다. 죽는 소리를 보스마다 바꿨다 (`getDeathSound`). 예고 입자가 없던 **수호자 졸개 부르기**에 둘레 2칸 마법 입자를 더했다 (나머지 패턴은 이미 있음).
- 입자 (클라이언트 `animateTick`, 켜졌을 때만): 정밀 조립기 = 앞면 전기 불꽃, 세척기 = 위로 물방울, 고압 정련기 = 김, 보일러 = 가끔 옆면 틈으로 김이 픽, 터빈 = 옆으로 김. 대형 보일러 · 보일러 · 터빈 위 김은 원래 있었다.
- 시험: 소리 등록 · sounds.json 항목 · 자막 번역 맞춤, 연료 넣은 분쇄기가 작동음을 낸다 (서버가 낸 수를 세는 시험용 카운터). 클라이언트 확인: 모든 소리를 클라이언트 소리 관리자가 알고 자막이 붙는지 + 한 번씩 틀기, 보일러 · 정밀 조립기 · 세척기 · 분쇄기를 돌려 서버 작동음 13번 (`m11b-machines.png`). 로그에 "Missing sound for event" · "Unable to play unknown soundEvent" · 없는 파일 경고 없음.
- 공허 거상 (마지막 묶음 fin에서 더함, 소리 16개): 끌어당기기 예고(워든 음파 충전, 낮게, 원래 예고 10틱 뒤 엔더맨 응시 소리 자리) · 수정 소환(신호기 켜짐, 낮게, 원래 엔드 차원문 틀 소리 자리) · 화남(워든 포효, 다른 보스의 공용 화남 소리 대신 `bossPhase`에 소리를 넘김, 입자는 역포탈) · 쓰러짐(위더 죽음, 낮게). 화남은 다른 보스처럼 체력이 절반 아래로 처음 내려갈 때 한 번 (불러오면 체력으로 다시 정함).
- 못 본 것: 실제로 귀로 듣는 크기 · 거슬림 (실테스트에서 설정으로 맞춤), 보스 소리는 시험에서 틀지 않음 (이름 · 정의만 확인. 거상 소리 넷은 클라이언트 확인에서 한 번씩 틀었다).

## C3 구현 메모 (강화 소환석)
**구현.** 수호자 · 파수꾼 · 거상 소환석에 강화 단계 +1 ~ +3 (거상은 마지막 묶음 fin에서 붙임). 코드는 `boss/`의 `BossTier`(단계 컴포넌트 · 배율 · 새 보스 붙이는 법은 이 클래스 주석) · `BossSummonerItem`(이름 "+N" · 툴팁) · `BossTierRecipe`(작업대 레시피 종류).
- 단계는 아이템 데이터 컴포넌트 `sanupcraft:boss_tier` (정수 0 ~ 3, 0이면 컴포넌트가 없어 강화 전과 똑같이 쌓인다). 단계가 다른 소환석은 서로 안 쌓인다.
- 강화: 작업대(모양 상관없음)에 소환석 하나 + 재료 → 단계 +1. 수호자 소환석 + **핵 조각 4개**, 파수꾼 소환석 + **파수꾼의 심장 1개**, 거상 소환석 + **공허 핵 1개**. +3은 더 못 올린다. 재료 수가 다르거나 다른 물건이 섞이면 안 맞는다. 레시피 종류 `sanupcraft:crafting_boss_tier` (`recipe/<보스>_summoner_upgrade.json`: summoner · material · count). 특수 레시피라서 레시피 책 · JEI에는 안 보이고, 소환석 툴팁(`.tooltip2`)이 만드는 법을 알려 준다.
- 소환: `GuardianAltarBlock`이 소환석 단계를 읽어 `summon(level, pos, type, tier)`에 넘기고, `BossParty.setTier`가 걸어 준다. 최대 체력 = 기본 x 인원 배율 x (1 + 0.5 단계) (수정자 둘이 곱으로 겹침: 인원은 `ADD_MULTIPLIED_BASE`, 단계는 `ADD_MULTIPLIED_TOTAL`), 공격력 속성 x (1 + 0.25 단계) (근접 공격). 패턴 피해(돌진 · 내려찍기 · 폭발 · 고리 · 도약)는 `hitWithRust` / `hitWithHeat`의 패턴 타격에서 `party.outgoingDamageScale()`을 곱한다 (전 이름 `damageScale`). 거상은 셜커 탄 피해(바닐라 4 고정)를 곱한다: 바닐라 탄을 상속한 `VoidColossus.VoidBullet`이 맞힐 때 피해만 바꿔 준다 (엔티티 종류는 바닐라 그대로라 저장했다 불러오면 바닐라 탄 = 4. 탄은 몇 초면 사라져서 둠). 끌어당기기는 피해가 없어서 그대로. 보스 바 제목은 "이름 +N" (`PartyBoss.refreshBossBar`, 이름표로 바꿔도 유지). 소환할 때 채팅으로 단계 · 체력 · 피해 증가를 알린다.
- 저장: 단계는 `party_tier`로 보스에 저장 (체력 · 공격력 수정자는 속성 저장으로 같이 돌아온다). 명령어(`summon`)로 부른 보스는 단계 0.
- 보상: `BossParty.giveKeyItem` 한 곳. 기여자 각자 핵 · 심장 `1 + 단계`개 + 기계 업그레이드 하나(속도 · 효율 · 두 배 중 무작위, 한 번에 하나). 기여자가 없으면 보스 자리에 핵 · 심장만 `1 + 단계`개 떨군다 (업그레이드 없음). 보스 기록(T2)의 `tier`에 단계를 넘겨서 기록판에 "강화 N단계"가 뜬다 (전에는 자리만 있었음).

## 마지막 묶음 (fin) 구현 메모
공허 거상을 다른 두 보스와 맞추고 (X1 전용 모델 · X2 효과음 · C3 강화 단계) 체력 상한 처리를 하나로 합쳤다. GameTest `SanupcraftFinGameTest` (8개), 클라이언트 확인 `SanupcraftFinClientGameTest` (스크린샷 `sanupcraft-fin-*.png`: 앞 · 비스듬히 · 옆 · 뒤 · 가까이 · 끌어당기기 예고 · 끌어당기는 중 · 수정 보호막 둘 · 내려치기 · 밤, 거상 소리 넷 틀기).

**보스 체력 상한 규칙** (`BossParty`, 세 보스 공통)
- 바닐라 최대 체력 속성은 1024에서 잘린다 (`BossParty.healthCap()`, 속성 정의에서 읽음). 원래 체력 = 기본 × 인원 배율 × 단계 배율 (`BossParty.intendedMaxHealth(boss)` — 따로 저장하지 않고 속성 수정자에서 속성 계산과 같은 순서로 다시 계산한다. 수정자는 속성 저장에 같이 남으므로 불러와도 같다).
- 원래 체력이 1024를 넘으면 최대 체력은 1024에 두고, **받는 피해 × 1024 / 원래 체력** (`party.incomingDamageScale(boss)`). 보스마다 `getDamageAfterMagicAbsorb`(갑옷 · 마법 보호 계산 뒤, 흡수 전)에서 곱한다 → 실제로 버티는 체력이 원래 값과 같다. 예: 수호자 5명 +3 = 300 × 3 × 2.5 = 2250 → 체력 1024, 받는 피해 × 0.455. 파수꾼 5명 +3 = 3375, 거상 5명 +3 = 4500.
- 체력 비율이 그대로 맞아서 보스 바 진행도(체력 / 최대 체력)는 손대지 않았다. 기여 5% 판정도 같은 비율이라 그대로.
- 이름: 보스가 주는 패턴 피해 배율은 `outgoingDamageScale()`, 받는 피해 배율은 `incomingDamageScale(boss)`. 거상에 있던 `uncappedMaxHealth` · `damageScale`(받는 쪽)은 지웠다. `/kill`처럼 무적을 뚫는 피해도 곱하지만 피해가 아주 커서 상관없다 (전에는 거상만 그런 피해를 빼고 곱했다).

**거상 그 밖**
- 불러올 때 보스 바 제목(+N)을 다시 쓰고 화남 알림을 체력으로 다시 정한다 (다른 보스와 같게. 전에는 거상만 빠져 있었다).
- 동기화 데이터 비트 `flags()`: 수정이 지키는 중 · 끌어당기기 예고 · 끌어당기는 중 (AI 틱마다 `updateFlags`). 모델 동작용.
- 시험: 수호자 · 파수꾼 · 거상 5명 +3 체력 상한 보정 (마법 피해로 10%를 깎으면 체력 비율 0.9, 원래 체력 − 10을 맞아도 살고 20을 더 맞으면 쓰러짐), 상한 밑은 보정 없음, 거상 소환석 강화(공허 핵 1개, +3에서 멈춤, 다른 재료 · 개수 안 됨, 이름 +N), 거상 단계 2 체력 · 공격력 · 셜커 탄 피해(4 → 6) · 보스 바 · 저장, 단계 1 거상 보상(공허 핵 2 + 업그레이드), 거상 소리 등록. 기존 시험의 `damageScale` · `uncappedMaxHealth` 이름을 새 이름으로 바꿨다 (C3 · M6). GameTest 292개 통과.
- 시험 주의: 상한 시험은 보스를 쓰러뜨린 뒤 바로 치운다 (쓰러지는 20틱 동안에도 근처 제단 시험이 보스로 세서 "제단이 수호자를 부르지 못함"이 났다).
- 못 본 것: 실제 엔드에서 강화 거상과 싸우기 (셜커 탄 6 · 7 체감), 여럿이서 1024를 넘는 보스를 잡을 때 보스 바가 줄어드는 속도 체감, 끌어당기기 · 보호막 동작을 실제 AI로 본 것 (클라이언트 확인은 NoAI 거상에 패턴 · 수정을 직접 걸어서 찍었다), 거상 소리를 실제 전투에서 듣기.

| G3 | 장비 모듈 | 갑옷 · 도구에 모듈 칸(청동 0, 강철 1, 크롬강 · 내열 2, 네더라이트 · 공허 3). 모듈(정밀 조립기 제작): 갑옷 = 자석 · 야간 투시 · 가스 필터 · 녹 방지 · 과열 방지 · 침식 방지 · 증기 추진(점프 강화); 도구 = 범위(3x3) · 효율 · 자동 제련 · 행운 · 섬세한 손길; 무기 = 연발 · 산탄(리벳총) · 넉백. **장비 작업대**(블록)에서 끼우고 뺌. 모듈은 아이템 데이터 컴포넌트 |
| G4 | 수리 · 계승 | **증기 수리대**: 장비 + 재료(그 장비 금속) + 증기로 내구 회복(마법 부여 · 모듈 유지). **계승**: 장비를 윗단계로 올리는 모든 레시피(강철 → 내열, 네더라이트 → 공허 등)가 마법 부여 · 모듈 · 이름을 옮긴다 |
| G5 | 특수 장비 | **잠수 헬멧**(증기 = 산소, 물속 시야), **광부 갑옷 한 벌**(헬멧 머리 조명 · 어둠 효과 막기 · 가스 감지 경고, 한 벌이면 채굴 속도 +20% · 낙하 −50%), **증기 파워 아머 한 벌**(증기 저장, 힘 II · 점프 · 넉백 저항, 가슴에 제트팩 모듈을 끼울 수 있음) |
| G6 | 멀티툴 | 증기 다목적 공구: 블록에 따라 곡괭이 · 삽 · 도끼 · 괭이로 자동 전환, 모듈 칸 3, 증기 4000. 드릴 · 전기톱 윗단계 |
