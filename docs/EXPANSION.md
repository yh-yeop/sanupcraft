# 확장 계획 2 · M7 ~ M11 (설계 2026-11-06)

A · B · C · M5 · M6 설계는 [ROADMAP.md](../ROADMAP.md)의 "확장 계획" 절. 여기는 그 뒤에 이어지는 M7 ~ M11.
묶음은 git worktree에서 동시에 구현하고 stage2에 합친다. 구현한 행은 "구현"으로 표시하고, 설계와 달라진 점을 그 행에 적는다.
숫자는 실테스트 전 초안이다. 조정할 만한 값은 `config/sanupcraft.json`(SanupcraftConfig)으로 뺀다.

## M9 · 생산 · 장비
| # | 추가 | 설계 |
|---|---|---|
| P1 | 작물 수확기 · 벌목기 | 수확기: 증기로 앞쪽 9x9 다 자란 작물을 거두고 씨앗으로 다시 심음, 9칸 저장. 벌목기: 앞의 나무를 통째로(원목 · 잎) 베고 묘목을 다시 심음 |
| P2 | 몹 분쇄기 · 경험치 탱크 | **구현.** 분쇄 칼날 블록: 위 칸 몹에게 피해(플레이어 처치처럼 전리품 · 경험치). 경험치는 액체(B2 탱크 · 경험치 탱크)로 모으고, 우클릭으로 꺼냄. 달라진 점: 블록 이름은 "몹 분쇄기"(`mob_grinder`)와 "경험치 탱크"(`experience_tank`, 따로 만든 블록). 경험치는 B2의 `FluidKind`에 `EXPERIENCE`로 더했다 (양동이 없음, 경험치 1점 = 20 mB, `FluidKind.MB_PER_XP`). 분쇄기는 증기 200을 모으고 기본 1초(20틱)마다 위 칸 몹에게 피해 6 (config `mobGrinder`: damage · steamPerHit 10 · ticksPerHit)을 준다 — Fabric API `FakePlayer`가 준 피해로 쳐서 "플레이어가 잡아야" 나오는 전리품 · 경험치가 나오고, 밀려나지도 가짜 플레이어를 쫓지도 않는다. 안 베는 것: 플레이어 · 길들인 동물 · 이름표 붙은 몹 · 주민 · 위더 · 엔더드래곤 · 워든 · 갑옷 거치대 · `PartyBoss`. 둘레 2칸 구슬(5틱마다)은 붙은 경험치 탱크 → 없거나 가득이면 분쇄기 안 저장고(200점, 빈손 우클릭으로 받음)로 모은다. 경험치 탱크 5000점, 빈손 우클릭 = 다음 레벨까지 모자란 만큼 (웅크리고 = 전부), 유리병 우클릭 = 10점으로 경험의 병, 비교기, 부수면 `sanupcraft:fluid` 컴포넌트로 보존 |
| P3 | 증기 제트팩 | 가슴 칸, 증기 3000 저장. 점프 키를 누르고 있는 동안 상승 (클라이언트 → 서버 패킷 필요), 틱당 증기 5 |
| P4 | 증기 드릴 · 전기톱 | 증기 저장 공구 (2000). 드릴 = 곡괭이+삽, 웅크리고 우클릭으로 1x1 / 3x3 모드. 전기톱 = 도끼, 나무를 통째로. 블록당 증기 10 |
| P5 | 배낭 | **구현.** 27칸 휴대 창고 (강철판 업그레이드로 54칸). 창고 네트워크와는 S6 휴대 단말로 연결. 달라진 점: 강철 배낭은 별도 아이템(`steel_backpack`)이고, 제작법은 `crafting_transmute`(배낭 + 강철판 4개, 내용 컴포넌트 보존). 내용은 `minecraft:container` 컴포넌트에 담고(`BackpackContainer`가 바뀔 때마다 되씀), 창은 `BackpackMenu`(바닐라 9x3 · 9x6 창 모양, 클라이언트는 바닐라 화면). 칸에 배낭을 넣을 수 없고, 열려 있는 배낭 자신은 집거나 옮길 수 없으며, 셜커 상자 · 묶음에도 못 들어간다 (`canFitInsideContainerItems` false) |

## M10 · 10명 서버 운영
| # | 추가 | 설계 |
|---|---|---|
| T1 | 팀 | **구현.** `/sanupcraft team create|join|leave|list`. 잠금(엔더 운반기 · 차원 창고 · 단말)이 주인 대신 팀에도 열림. 팀 이름 색 · 이름표. 달라진 점: 이름은 줄 끝까지 읽어서 한글도 되고(`create <이름>`), 색은 `color <색>`으로 따로 바꾼다. 열림이 기본이고 주인이 `lock`으로 잠그면 새로 못 들어온다. 주인은 `kick <이름>`으로 내보낼 수 있다. 주인이 나가면 다음 사람이 주인, 마지막 사람이 나가면 팀이 사라진다. 이 모드의 팀(`data/sanupcraft/teams.dat`)이 정본이고 바닐라 스코어보드 팀(`sc_<번호>`)에 같이 맞춰서 이름표 · 채팅에 `[팀 이름]`과 색이 붙는다. **다른 묶음(차원 창고 · 단말)은 잠금 검사에 `server.Teams.sameTeam(level, owner, player)`를 한 줄 더하면 된다** (엔더 운반기는 `canManage`에 넣어 둠) |
| T2 | 보스 기록판 | **구현.** 블록. 보스별 최고 기록(처치 시간 · 참가자 · 강화 단계)을 서버 전체 저장 데이터로 보여 줌. 달라진 점: 빈손 우클릭하면 보스마다 상위 3개를 채팅으로 보여 준다 (글자판 렌더러는 안 만듦). 보스가 소환 시각을 들고 있다가(`BossParty` 저장 필드 `party_summoned`) 보상을 줄 때 `BossRecords.record`가 소환~처치 시간 · 기여자 이름 · 소환 때 인원을 `data/sanupcraft/boss_records.dat`에 남긴다 (보스마다 상위 10개). 제단이 아니라 명령어로 불러낸 보스나 기여자가 없는 처치는 남기지 않는다. 강화 단계는 자리만 있다 (`tier`, 지금은 0이라 표시 안 함). 1위를 세우면 서버 전체에, 아니면 기여자에게 알린다 |
| T3 | 공용 목표판 | **구현.** 블록. 관리자가 정한(또는 기본) 목표 "강철 주괴 1000개" 등에 아이템을 넣어 서버 전체가 채움. 다 차면 모두에게 알림 + 보상 상자. 달라진 점: 판마다 목표 하나, 진행도는 블록 엔티티에 저장 (부수면 사라짐). 기본 목표는 코드(`server/Goals`)의 강철 주괴 1000 → 철판 2000 → 리벳 5000 → 기계 부품 500을 돌고, 다 채우면 다음 기본 목표로 넘어간다. 넣는 법: 목표 아이템 들고 우클릭(든 것 전부, 크리에이티브는 줄지 않음) 또는 깔때기 · 벨트. 빈손 우클릭 = 진행도, 웅크리고 빈손 우클릭 = 많이 넣은 사람 3명. 관리자는 `/sanupcraft goal set <아이템> <개수>`로 바라보는 판의 목표를 바꾼다 (진행도 0; 우클릭으로 정하는 방법은 안 만듦). 다 차면 전체 알림 → 손으로 넣은 접속자에게 발전 과제 "함께하는 공장" → 판 위(안 되면 옆)에 전리품 상자(`sanupcraft:goal_reward`) |
| T4 | 설명서 | **구현.** 처음 들어오면 받는 책 (서적 화면). 단계별 길잡이 · 기계 사용법 · 보스 공략. 한국어. 달라진 점: 바닐라 책이 아니라 `written_book_content`를 기본 컴포넌트로 가진 아이템 `sanupcraft:guide_book`이다 (그래서 레시피로 만들어도 내용이 같다). 14쪽, 글은 언어 파일 `book.sanupcraft.guide.1~14` (한국어 · 영어). 처음 접속에 한 번만 지급(받은 명단 `data/sanupcraft/guide_given.dat`), 책 + 철판으로도 만든다. 모양은 바닐라 완성된 책을 쓴다 |
